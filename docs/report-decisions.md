# Report and methodology decision register

Last updated: **26 October 2026 (Africa/Lagos)**. Scope: decisions agreed in the report discussion, associated implementation evidence, and remaining questions. This register preserves the distinction between the HOD's broad brief, the team's design choices, and verified software/hardware behaviour.

## How this register is maintained

- Add or amend the relevant stable ID whenever the owner makes a decision. Record the date, requirement, status and evidence or open question together; retain a change note when a decision is superseded.
- **Agreed** means an owner-approved requirement. **Implemented** means repository evidence supports the stated limited behaviour; it does not mean deployed or physically validated. **In progress** means work is underway but not yet accepted. **Open** means a decision or evidence is missing. Never silently convert one status to another.
- The active full-report source is [report-prototype/chapter_3.tex](report-review/report-prototype/chapter_3.tex), included by [main.tex](report-review/report-prototype/main.tex). The dated Markdown chapter draft and `source-notes/` copies are historical source material, not a synchronised second editor. Make current prose changes in the active `.tex` and record their rationale here.
- Update this register alongside implementation/report changes during active work. It is an ordinary version-controlled document, not a scheduled or background service. Do not copy private student data or fingerprint payloads into it.

Current implementation checkpoint: the [attendance reconciliation API](attendance-reconciliation.md) provides reference metadata mapping, paginated archive/review states, explicit evidence-backed resolution, audited meeting finalisation and per-course rates. GET/POST `/api/attendance/sessions/{meeting_uuid}/finalisation/` requires correction-authorised course staff, closed collection, `reviewed: true`, a substantive reason and the expected reviewed digest. Source-evidence and confirmed-record snapshots reject stale confirmation; new imported source evidence invalidates the archive override. Exact replay is idempotent. Archived captures remain unchanged and can later be deliberately resolved; later audited corrections/resolutions update rates without deleting the original review snapshot.

Finalisation is optional for already fully reconciled/manual closed meetings that retain their established eligibility. It is an explicit reviewed override for unresolved, empty or interrupted-recovery evidence; **closing collection does not automatically finalise**. Rates expose pending/finalised/stale counts and return null for an empty denominator. Present/absent are the only attendance states. Formal-excuse exclusion is approved and implemented separately from attendance evidence (A09); no late penalty applies.

Retrospective-excuse checkpoint (25 October): the excusals endpoint accepts `retrospective: true` explicitly for a historical out-of-snapshot student who belongs to the later current HOD-approved course roster. Responses/audit identify retrospective scope, historical roster membership and eligibility roster revision. No historical student-list, presence or absence is inserted or rewritten. A separate `retrospective_excused_meetings` count documents closed prior-meeting excuses without changing the original numerator, denominator or ordinary excused count; a student with no eligible meetings can still have a zero-denominator/null-rate row. Later roster removal blocks new/re-granted retrospective excuses but permits revocation or exact replay of the earlier audit. This is not authority to backfill past presence. Final verification passed 53 focused tests (23 reconciliation and 30 existing attendance tests), system/migration-drift checks and scoped diff checks. Migration0007 was generated only and was not applied to a live database.

Formal-excuse API: GET/POST `/api/attendance/sessions/{meeting_uuid}/excusals/` uses the established assigned-staff correction permission and historical roster, with the explicit bounded A11 retrospective exception. POST records `student`, `event_id`, `is_excused` and a reason, preserving present/absent records and capture evidence. Grant/revoke is audited and exact event retry returns the original receipt without reapplying an old decision. Excused meetings contribute neither attendance nor eligible meetings for that student, including where a present record exists; an all-excused denominator returns no percentage. `excused_meetings` can overlap review/pending/finalised counters because review state remains visible independently of exemption. The finalisation review includes current excusals and action metadata, rejects concurrent review changes and retains `last_reviewed_excusals`; later audited grant/revoke updates rates without discarding source approval. The owner approved direct course-assigned staff authority and a written reason on 24 October 2026; no HOD preapproval or supporting document is required. No late penalty applies.
